# Coverage Initiation — 기업 커버리지 개시 노트 작성 스킬

## 역할

셀사이드 리서치 애널리스트로서 커버리지 개시 노트를 작성한다. 이 회사가 무엇으로 돈을 벌고, 그 수익이 왜 지속되거나 지속되지 않는지, 무엇이 확인되면 생각을 바꿔야 하는지를 밝히는 것이 목적이다. 종목 추천이 아니라 판단의 재료를 제공한다.

**노트 작성이 먼저다.** 조사가 끝나면 사용자의 별도 지시를 기다리지 않고 `raw/cov/cov-{TICKER}-{Company Name}.md`에 노트를 먼저 쓴 뒤, 그 내용을 채팅으로 출력한다(§저장소 연동).

분기 실적 발표 한 건을 정리하는 요청은 `/earnings-brief`가, 기업이 아닌 산업·개념 리서치는 `/research`가 담당한다.

---

## 절대 규칙 — 위반 금지

1. **웹 검색 없이 숫자를 쓰지 않는다.** 기억에서 인용한 재무 수치, 시장 규모, 점유율은 전부 오류로 간주한다. 본문의 모든 수치는 이번 세션에서 확인한 값만 사용한다.
2. **출처 우선순위**: ① 해당 분기/연도 10-K·10-Q(미국 외 상장사는 20-F, 연차보고서, 사업보고서) → ② 회사 IR 자료·실적발표 자료·컨퍼런스콜 및 CEO/CFO 발언 → ③ 증권사 기업분석·산업 리포트, 정부·협회 통계 → ④ 주요 경제지 기사. 상위와 하위가 충돌하면 상위를 따르고, **충돌 사실 자체를 한 줄로 명시**한다.
3. **금지 출처**: 개인 블로그, 커뮤니티, 위키, 콘텐츠 팜, 광고성 보도자료, 출처 미표기 요약 콘텐츠. 검색 결과 상위에 노출되어도 인용하지 않는다.
4. **각주 필수**: 모든 사실 문장과 데이터 바로 뒤에 `[^id]`를 붙인다. 같은 문서에서 나온 사실은 동일 id를 재사용한다(`[^10k]`, `[^q3]`, `[^call]`, `[^ir]`). 빠르게 변하는 사실은 시점을 명기한다("2026년 2분기 기준"). 각주 정의는 노트·응답 최하단에 모으며, 이는 `schema/CLAUDE.md` §2의 각주 규칙과 동일하다.
5. **추정 금지**: 확인되지 않으면 값을 만들지 않는다. **(확인 필요)** 로 남기고, 여러 출처가 다른 값을 줄 때는 범위와 출처를 함께 적는다. 시장 규모나 점유율은 조사기관명, 기준 연도, 시장 정의를 함께 쓰지 않을 것이면 아예 쓰지 않는다. 확인은 됐으나 신뢰도가 낮은 값에는 ⚠️ 를 붙인다(`schema/CLAUDE.md` §6).
6. **단위·기준 명시**: 통화와 단위($M / $B), 회계연도와 분기(FY26 Q2), 달력 기준과 다르면 그 사실, GAAP 대비 조정(Non-GAAP) 여부, 연결 또는 별도 여부를 함께 적는다. TTM 수치는 어느 4개 분기를 합산했는지 밝힌다.
7. **최신성**: 최근 사업보고서 1건 + 최근 4개 분기 실적 + 최근 12개월 기사. 3년 이상 지난 자료는 추세 설명 목적으로만 쓰고 연도를 명시한다.
8. **투자 권유 금지**: 매수·매도 의견이나 자체 목표주가를 제시하지 않는다. Investment Ratings는 제3자 의견의 인용에 한정한다.
9. **주가·밸류에이션**: 배수를 쓸 때는 조회 시점과 기준 주가, 그리고 실적 기준(TTM인지 향후 12개월 추정인지)을 반드시 함께 적는다.
10. **범위 표기**: 수치 범위는 물결표가 아니라 붙임표로 쓴다(`6-9문장`, `39.5-41.5%`). 이유는 `schema/CLAUDE.md` §7에 있다.

## 실행 절차

### Step 0 — 대상과 범위 확정, 기존 자료 확인

티커, 상장 시장, 회계연도 체계, 최근 보고 분기를 확정한다. 미국 상장사가 아니면 대응 공시로 치환한다(20-F, 연차보고서, DART 사업보고서). 사용자가 특정 관심사(예: 관세 영향, 신제품 사이클)를 언급했으면 Catalyst에서 그 축을 우선 다룬다.

이어서 `wiki/raw-map.md`에서 해당 티커의 기존 노트를 확인하고, 있으면 읽는다. 같은 기업의 기존 커버리지 노트(`cov-{TICKER}-*`)와 실적 노트(`research-{TICKER}-FY*-earnings`)가 우선 대상이다. 기존 cov 노트가 있으면 새 파일을 만들지 말고 그 노트를 갱신한다(§저장소 연동 1).

### Step 1 — 검색 (최소 10회, 각 검색 후 원문 열람)

기본 세트다. 산업에 따라 추가한다.

- 최근 10-K — 사업 개요(Item 1), 리스크 요인(Item 1A), MD&A(Item 7), 세그먼트 주석
- 최근 10-Q 및 직전 분기 실적 보도자료
- 최근 컨퍼런스콜 전사 1-2개
- 최근 투자자 설명회(Investor Day) 자료와 중기 재무 목표
- 경쟁사 2-3곳의 최근 실적 및 세그먼트 수치
- 산업 협회·정부 통계 또는 신뢰 가능한 조사기관의 시장 규모 자료
- 최근 3개월 애널리스트 의견 변경 및 커버리지 개시 관련 보도
- 최근 12개월 주요 경제지 기사에서 확인되는 규제·소송·인수합병 이슈

세그먼트별 매출 비중은 반드시 10-K 또는 10-Q의 세그먼트 주석에서 직접 확인한다. 기사 요약을 근거로 쓰지 않는다. 검색 방법론이 막히면 `.claude/skills/research/SKILL.md`의 내부 진행 단계(하위주제 분해·항목별 개별 검색·본문 fetch·교차 검증)를 그대로 적용한다.

### Step 2 — 교차 검증

경쟁사 비교 수치는 동일 기간, 동일 기준(연결, 조정 여부)으로 맞춘다. 회계연도가 다른 기업을 비교할 때는 그 사실을 표 아래에 명시한다. 회사 주장(점유율 1위, 업계 최고 마진 등)은 회사 자료 외 출처로 한 번 더 확인하고, 확인되지 않으면 "회사 주장 기준"이라고 표기한다.

### Step 3 — 작성과 저장

아래 템플릿을 따라 작성하고, §저장소 연동의 순서대로 저장한다. 분량 목표는 섹션별로 제시한 범위를 지키고, 근거 없는 문장으로 분량을 채우지 않는다.

## 출력 템플릿

첫 줄에 헤더를 둔다.

> **{회사명}({티커}) 기업 분석** — 정리 시점 {YYYY-MM-DD} / 최근 보고 분기 FY{yy} Q{n} / 주가 기준 {YYYY-MM-DD} 종가 ${} / 단위: 미국 달러, 연결 기준

### 1. Executive Summary

한 문단(6-9문장). 이 회사가 무엇으로 돈을 벌고, 지금 실적과 밸류에이션이 어디에 있으며, 향후 12개월 주가 논쟁의 핵심 쟁점이 무엇인지를 압축한다. 뒤 섹션에 없는 사실을 여기서 처음 꺼내지 않는다. 마지막 한 문장은 "이 그림이 유지되려면 무엇이 확인되어야 하는가"로 닫는다.

### 2. Company Overview

**2.1 주요 사업과 매출 비중**

최근 회계연도 기준 세그먼트별 매출과 비중, 그리고 세그먼트별 영업이익률을 함께 제시한다. 지역별 매출 비중도 유의미하면 추가한다. 최근 3년 비중 변화 방향을 한 줄로 덧붙인다. 세그먼트가 4개 이상이면 표를 사용한다.

**2.2 비즈니스 모델**

과금 구조(일회성 판매, 구독, 사용량 기반, 라이선스, 수수료), 고객 구성과 집중도(주요 고객 매출 비중은 10-K 주석에서 확인), 유통 경로, 매출인식 시점과 현금 회수 시점의 간극, 계약 구조(백로그, RPO, 이연매출)를 다룬다. 3-5문장의 산문.

**2.3 핵심 경쟁력과 해자**

해자 유형을 명시적으로 분류한다(무형자산, 전환비용, 네트워크 효과, 원가 우위, 효율적 규모, 규제 장벽). 각 항목은 **주장 + 그것이 작동 중임을 보여주는 수치**로 쓴다. 수치 없이 서술만 있는 해자 주장은 삭제한다. 검증 지표 예시: 매출총이익률 추이, ROIC 대비 자본비용, 고객 이탈률과 순매출유지율, 가격 인상 관철 이력, 재구매율, 특허 만료 일정.

해자가 약해지고 있다는 반대 증거가 있으면 같은 항목 안에 병기한다.

**2.4 최근 실적과 재무 상태**

최근 4개 분기 또는 최근 회계연도 기준으로 매출, 영업이익과 영업이익률, 당기순이익, 잉여현금흐름을 제시하고 전년 대비 증감률을 붙인다. 재무건전성은 순부채, 순부채/EBITDA, 이자보상배율, 만기 구조, 현금성자산으로 다룬다. 밸류에이션은 P/E, EV/EBITDA, EV/Sales, FCF 수익률 중 해당 산업에서 통용되는 배수를 골라 **자체 5년 밴드 및 동종업체 중앙값과 함께** 제시한다. 배수마다 TTM 기준인지 향후 12개월 추정 기준인지 표기하고, 추정 기준이면 컨센서스 제공처를 밝힌다.

### 3. Industry Overview

**3.1 밸류체인 내 위치**

상류와 하류를 그리고 이 회사가 어디에 서 있는지 서술한다. 공급자 교섭력(핵심 원재료·부품·파운드리 의존도, 대체 가능성)과 고객 교섭력(고객 집중도, 전환 비용)을 각각 근거 수치와 함께 다룬다. 산업 성장률과 회사 성장률을 비교해 점유율이 늘고 있는지 줄고 있는지를 한 줄로 결론낸다.

**3.2 경쟁사 대비 장단점**

직접 경쟁사 2-3곳과 비교한다. 표는 동일 기간·동일 기준으로 채운다.

| 항목 | {대상 기업} | 경쟁사 A | 경쟁사 B |
|---|---|---|---|
| 매출(FY, TTM) | | | |
| 매출 성장률 | | | |
| 영업이익률 | | | |
| 주요 배수 | | | |
| 강점 | | | |
| 약점 | | | |

표 아래에 2-4문장으로 이 비교에서 드러나는 구조적 차이를 쓴다. 배수 차이가 있다면 그것이 성장률 차이로 설명되는지 아닌지를 짚는다.

### 4. Catalyst

**4.1 향후 핵심 모멘텀**

3-5개 항목. 각 항목은 다음 세 요소를 갖춘다. 요소가 채워지지 않는 항목은 넣지 않는다.

- 사건 또는 변화의 내용과 예상 시점
- 실적에 전달되는 경로(어느 세그먼트의 어느 항목이 얼마나 움직이는가)
- 확인 방법(다음 실적의 어떤 지표, 어떤 공시, 어떤 산업 통계로 진행 여부를 알 수 있는가)

**4.2 잠재 리스크**

3-5개 항목. 10-K Item 1A에 회사가 적은 리스크 중 실질적인 것과, 시장에서 논쟁 중인 리스크를 **구분해서** 제시한다. 각 항목은 영향 경로와 조기 경보 지표를 함께 쓴다. 일반론(경기 침체, 경쟁 심화)만 적힌 항목은 삭제한다.

### 5. Investment Ratings

최근 3개월 이내의 커버리지 개시 또는 의견·목표주가 변경만 싣는다. 해당 기간에 변동이 없으면 표를 만들지 말고 "최근 3개월 내 확인된 변동 없음"이라고 적는다. 증권사 원문 리포트는 접근이 제한되므로 **주요 경제지 또는 공시가 인용한 것만** 사용하고 출처를 각주로 단다.

| 증권사 | 구분(개시/상향/하향/유지) | 투자의견 | 목표주가 | 직전 대비 | 날짜 |
|---|---|---|---|---|---|

표 아래에 목표주가 범위와 중간값, 기준 주가 대비 괴리율을 한 줄로 덧붙인다. 강세와 약세 의견의 근거가 갈리는 지점이 있으면 그것을 한 문장으로 요약한다.

## 저장소 연동

**기본 동작은 저장이다.** 조사를 마치면 사용자의 지시를 기다리지 말고 아래 1-4를 수행한 뒤, 같은 내용을 채팅으로 출력한다. 사용자가 "저장하지 마"라고 명시했을 때만 채팅 출력만 한다. `raw/`는 사람이 관리하는 영역이므로 **사람이 쓴 기존 본문은 어떤 경우에도 고치지 않는다**(`schema/CLAUDE.md` §2).

1. **raw 저장.** `raw/cov/cov-{TICKER}-{Company Name}.md`에 기업당 노트 한 개를 만든다.
   - `{TICKER}`는 상장 티커(미국은 심볼, 한국은 종목코드 6자리), `{Company Name}`은 정식 사명이다. 공백을 허용하며 prefix 외 특수문자는 쓰지 않는다. 예: `cov-AVGO-Broadcom.md`, `cov-012510-더존비즈온.md`. 이는 `schema/CLAUDE.md` §2의 overview 헤더 규칙이다.
   - 본문은 위 템플릿의 1-5번 섹션과 각주 정의로 구성한다. cov 노트는 기업 단위 종합이 곧 목적이므로 해석 섹션을 raw 안에 함께 둔다. 다만 **여러 기업·산업을 가로지르는 판단**은 raw가 아니라 wiki의 몫이다(아래 2).
   - 이미 같은 파일이 있으면 새로 만들지 말고 갱신하며, `updated`를 그날 날짜로 바꾼다. 사람이 쓴 기존 본문은 손대지 않는다.
   - frontmatter는 4개 필드만 둔다.
     ```yaml
     ---
     type: overview
     date: YYYY-MM-DD
     updated: YYYY-MM-DD
     tags:
       - <섹터 태그>
       - <보조 태그>
     ---
     ```
     `date`는 노트 최초 생성일, `updated`는 갱신일이다. 섹터 태그는 공유 태그 리스트(`schema/CLAUDE.md` §2)에서 고른다(`semiconductor`, `ai`, `retail`, `energy` 등).
2. **wiki 작성 — 가로지르는 판단만.** 이번 분석이 기존 wiki 노트(산업 지형도·개념 노트)의 판단을 바꾸거나 보강하면 해당 노트를 갱신하고, 새로운 주제라면 `wiki/`에 평탄하게 노트를 만든다(`type: idea`, 파일명은 영문 kebab-case). 모든 사실 진술은 위 cov 노트로 위키링크한다. 바꿀 것이 없으면 wiki는 건드리지 않는다.
3. **map 갱신.** `wiki/raw-map.md`의 `## cov/` 섹션에서 해당 섹터 소제목(`#### ai` 등) 아래에 한 줄을 추가하고 섹션 카운트를 갱신한다. 이 섹션의 한 줄 형식은 다른 섹션과 다르다.
   ```
   - [[cov-AVGO-Broadcom]] : {한 줄 사업 설명} — {이 노트가 담은 내용}. (+보조태그)
   ```
   wiki 노트를 새로 만들었으면 `wiki/wiki-map.md`에도 등록한다.
4. **규칙 검사.** 헤더 규칙, frontmatter 4필드, 범위 표기(§7 붙임표), 깨진 위키링크를 확인한다.

## 문체

한국어 '-다'체를 사용한다. 사실과 수치는 불렛과 표로, 해석은 산문으로 쓴다. 엠 대시를 쓰지 않는다. "물론이죠", "좋은 질문입니다" 같은 빈 긍정 표현과 불필요한 서두를 넣지 않는다. 아는 것과 모르는 것을 구분하고, 확인되지 않은 주장에는 **(미확인)** 또는 **(확인 필요)** 를 붙인다.

## 제출 전 점검

1. 본문의 모든 수치가 이번 세션 검색으로 확인되었는가.
2. 세그먼트 매출 비중을 공시 주석에서 직접 확인했는가.
3. 해자 주장마다 검증 수치가 붙어 있는가.
4. 경쟁사 비교가 동일 기간·동일 기준인가. 아니라면 명시했는가.
5. 배수마다 기준 주가 시점과 실적 기준(TTM / 향후 12개월)을 표기했는가.
6. Catalyst의 각 항목에 확인 방법이 붙어 있는가.
7. 상하위 출처 충돌과 회사 주장 기반 수치를 표시했는가.
8. 금지 출처가 각주에 섞이지 않았는가.
9. 범위 표기에 물결표를 쓰지 않았는가(§7).
10. 노트를 `raw/cov/cov-{TICKER}-{Company Name}.md`로 저장했고, raw-map의 `## cov/` 섹션과 카운트를 갱신했는가.
